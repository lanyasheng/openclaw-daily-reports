【1】AgenticCyOps：企业网络运营中的多智能体安全框架
https://arxiv.org/abs/2603.09134v1
发布：2026-03-10 | 分类：cs.CR, cs.MA, cs.SE

中文解读：该论文首次系统性地分析了多智能体系统（MAS）在企业网络运营中的攻击面问题。传统确定性流水线不存在的安全风险，在赋予 Agent 自主控制权后集中爆发：工具调用、记忆访问、跨 Agent 通信均可被恶意利用。作者提出 AgenticCyOps 安全框架，包含三层防护：(1) 工具调用前的意图验证层，(2) 记忆访问的隔离与审计层，(3) Agent 间通信的信任链验证。实验显示该框架可阻断 94% 的已知攻击向量，同时保持 97% 的正常任务完成率。

影响评估：⭐⭐⭐⭐⭐ 企业级 Agent 部署的必读安全指南，尤其适合正在构建多 Agent 工作流的团队。

【2】Governed Memory：多智能体工作流的生产级记忆架构
https://arxiv.org/abs/2603.17787v1
发布：2026-03-18 | 分类：cs.AI, cs.CL, cs.MA

中文解读：当前企业 AI 部署中，数十个独立 Agent 节点操作同一实体却无共享记忆和统一治理，导致五大结构性挑战：记忆孤岛、治理碎片化、状态不一致、审计困难、恢复复杂。论文提出 Governed Memory 架构，核心创新包括：(1) 统一记忆层（Unified Memory Layer）支持跨 Agent 状态同步，(2) 治理策略引擎（Governance Policy Engine）实现细粒度访问控制，(3) 版本化记忆快照支持回滚与审计。在金融客服场景的实测中，该架构将任务冲突率降低 76%，审计效率提升 3.2 倍。

影响评估：⭐⭐⭐⭐⭐ 解决多 Agent 协作中最核心的记忆一致性问题，架构设计可直接借鉴。

【3】Model-First Reasoning：通过显式问题建模减少 LLM Agent 幻觉
https://arxiv.org/abs/2512.14474v1
发布：2025-12-16 | 分类：cs.AI

中文解读：针对 LLM 在复杂多步规划任务中约束违反率高、解不一致的问题，论文提出 Model-First Reasoning（MFR）方法。与 Chain-of-Thought 和 ReAct 依赖隐式状态跟踪不同，MFR 要求 Agent 在推理前显式构建问题模型：包括状态空间定义、约束条件形式化、目标函数明确化。实验在 5 个规划基准测试中，MFR 将约束违反率从 34% 降至 8%，解一致性从 61% 提升至 89%。关键洞察：显式建模迫使 LLM 在推理前"想清楚"，而非"边做边想"。

影响评估：⭐⭐⭐⭐ 对需要高可靠性规划的场景（如自动化运维、机器人控制）有直接应用价值。

【4】RepoReviewer：仓库级代码审查的本地优先多智能体架构
https://arxiv.org/abs/2603.16107v1
发布：2026-03-17 | 分类：cs.SE, cs.AI

中文解读：仓库级代码审查需要同时理解项目结构、仓库上下文和文件级实现细节。现有自动化审查往往将这些任务压缩为单次处理，导致相关性下降、重复增加、优先级混乱。RepoReviewer 提出本地优先的多 Agent 架构：(1) 结构分析 Agent 负责理解项目拓扑，(2) 上下文 Agent 维护变更历史与依赖关系，(3) 实现审查 Agent 聚焦具体代码逻辑，(4) 优先级 Agent 整合输出并排序。在 12 个开源项目的评测中，RepoReviewer 的审查质量（人工评分）比单 Agent 方案高 42%，重复报告减少 67%。

影响评估：⭐⭐⭐⭐ 为 AI 代码审查提供了可扩展的架构范式，适合集成到 CI/CD 流程。

【5】Protein Design with Agent Rosetta：专业科学 Agent 的案例研究
https://arxiv.org/abs/2603.15952v1
发布：2026-03-16 | 分类：cs.AI

中文解读：论文以蛋白质设计为测试床，探索专用科学 Agent 的构建方法。现有 ML 方法虽在蛋白质设计任务上表现优异，但局限于预定义任务且缺乏可解释性。Agent Rosetta 的核心设计：(1) 工具层集成 Rosetta、AlphaFold 等专业工具，(2) 规划层支持多目标优化（稳定性、可合成性、功能活性），(3) 验证层自动运行分子动力学模拟进行结果校验。在 3 个蛋白质设计基准上，Agent Rosetta 达到 SOTA 水平的同时，提供完整的决策链解释。

影响评估：⭐⭐⭐⭐ 为科学计算领域的 Agent 应用提供了可复用的架构模板。

【6】GNNVerifier：基于图的 LLM 任务规划验证器
https://arxiv.org/abs/2603.14730v2
发布：2026-03-16 | 分类：cs.LG

中文解读：LLM 生成的任务规划常因幻觉和对长上下文敏感而产生错误。GNNVerifier 将任务规划表示为有向图（节点=子任务，边=依赖关系），使用图神经网络验证：(1) 可达性检查（目标是否可达），(2) 循环依赖检测，(3) 资源约束验证，(4) 时序一致性检查。在 WebArena 和 ALFWorld 基准上，GNNVerifier 将规划执行成功率从 54% 提升至 78%，且验证开销仅增加 12%。

影响评估：⭐⭐⭐⭐ 轻量级验证方案，可直接嵌入现有 Agent 框架作为规划质量过滤器。

【7】Don't Trust Stubborn Neighbors：智能体网络的安全框架
https://arxiv.org/abs/2603.15809v1
发布：2026-03-16 | 分类：cs.MA, cs.AI

中文解读：多智能体系统的交互性引入新安全风险：恶意或被攻陷的 Agent 可利用通信机制传播错误信息、操纵协作决策、发起级联攻击。论文提出基于"有限信任"的安全框架：(1) 动态信任评分（基于历史行为一致性），(2) 消息来源验证（密码学签名 + 语义一致性检查），(3) 异常传播隔离（检测到异常时自动切断通信链路）。在模拟攻击场景中，该框架将系统被攻陷时间从平均 4.2 分钟延长至 37 分钟。

影响评估：⭐⭐⭐⭐ 对开放环境中的多 Agent 协作（如跨组织工作流）有重要参考价值。

【8】AI Planning Framework for LLM-Based Web Agents
https://arxiv.org/abs/2603.12710v1
发布：2026-03-13 | 分类：cs.AI, cs.CL

中文解读：针对 Web 任务 Agent 作为黑盒难以诊断失败原因的问题，论文提出形式化规划框架：将 Web 任务建模为 PDDL（Planning Domain Definition Language）问题，LLM 负责自然语言到 PDDL 的转换，经典规划器负责求解。优势：(1) 规划过程可解释（可输出规划轨迹），(2) 失败可诊断（可定位约束冲突点），(3) 支持增量修复（局部重规划而非全量重试）。在 Mind2Web 基准上，该框架的任务完成率比纯 LLM 方案高 23%。

影响评估：⭐⭐⭐ 适合需要高可解释性的 Web 自动化场景（如 RPA、测试自动化）。
