**新增新闻**

1. **英国金融监管部门紧急评估 Anthropic 最新模型风险** [来源](https://www.ft.com/content/ec7bb366-9643-47ce-9909-fc5ad4864ae5)

2. **OpenAI Academy 上线 Projects 教程，ChatGPT 正加速走向持续工作空间** [来源](https://openai.com/academy/projects)
   OpenAI 把 Projects 定义为组织聊天、文件、指令与持续工作的容器，这说明产品重心正在从“单轮对话窗口”转向“长期任务工作台”。这类设计本质上是在补齐 Agent 真正落地所需的状态管理层，让同一项工作可以跨时间、跨材料、跨协作者延续。它也和今天晨间的 Skills 叙事形成呼应，说明大厂在同时推进“能力封装”和“工作空间封装”。**影响评估：2026 年 Agent 产品竞争会越来越像工作流软件竞争，谁能稳住长期上下文和协作结构，谁就更接近企业入口。**

3. **OpenAI 推出 ChatGPT for Marketing Teams 教程，部门级工作流开始模板化** [来源](https://openai.com/academy/marketing)
   这篇教程不是在讲一个新模型，而是在教市场团队如何用 ChatGPT 做 campaign planning、内容生成和效果分析，代表产品叙事正从通用助手切向垂直职能场景。它的信号很清楚，平台方已经在尝试把 AI 价值包装成“部门可直接采用的 SOP”，而不是留给用户自己摸索提示词。对 Agent 生态而言，这意味着未来竞争不只是模型能力，而是谁先拿下市场、销售、客服、研发等部门的标准工作流模板。**影响评估：部门级模板化将成为 AI 工具扩张的关键手段，工作流沉淀能力会比单次生成质量更有复利。**

4. **nb-cli 试图把 Jupyter Notebook 变成“人类与 Agent 共用”的命令行界面** [来源](https://github.com/jupyter-ai-contrib/nb-cli)
   这个项目主打面向 humans and AI agents 的 Notebook CLI，把原本偏图形交互的 notebook 工作流暴露成更适合自动化与编排的接口。对研究、数据分析和实验型工作流来说，这一步很关键，因为 Agent 只有进入 CLI/API 层，才可能稳定接入版本控制、批处理和多步骤编排。当前线索主要来自 GitHub 与 HN，仍属单源扩散，建议后续继续核实真实采用情况。**影响评估：Notebook 工具链正在 Agent-Native 化，数据科学工作流可能成为继 coding workflow 之后的下一块编排高地。**

5. **“强模型优先还是弱模型优先”成为多步 Agent 的显性成本议题** [来源](https://llm-spec.pages.dev/)
   这项公开页面讨论多步 LLM Agent 中，究竟应该把强模型放在前置规划、后置验证，还是只在关键节点调用，核心问题已经不是“能不能做”，而是“怎样做更划算”。这类研究很贴近真实生产环境，因为多步 Agent 的成本往往并非由单次调用决定，而是由整条链路的模型分配策略决定。它和近期行业对 routing、harness、quality gate 的关注高度一致，说明模型编排正在变成一门独立工程学。**影响评估：任务到模型的路由策略会成为 Agent 基础设施核心能力，低成本高质量的关键不在单模型，而在调度设计。**

6. **Android 应用操作型 Agent 再冒头，Sova 宣称无需 root/ADB/PC 即可控制 App** [来源](https://news.ycombinator.com/item?id=47738583)
   这条 HN 帖子展示的是一个可直接操作手机应用的 Android agent-assistant，强调不依赖 root、ADB 或 PC 辅助。如果能力属实，它意味着移动端 Agent 正试图摆脱“只能聊天”的定位，转而进入真正的系统操作层。虽然目前仍是 Show HN 阶段，可信度和稳定性都需要继续验证，但方向上很值得看，因为移动操作自动化一直是高频但难做的场景。**影响评估：Web Agent 之后，移动端应用操作可能成为下一波 Agent 入口争夺点，但短期仍要警惕演示与真实可用性之间的落差。**

7. **claude-mem 继续走强，编码会话记忆插件升至 4.85 万星** [来源](https://github.com/thedotmack/claude-mem)
   claude-mem 的定位非常直接，就是自动捕获编码会话、压缩上下文，再把相关记忆注回后续 session，本质上是在给 coding agent 补上项目级长期记忆层。它和今天白天关于 harness 与 memory 的讨论形成了非常强的产品侧闭环，说明“记忆”已经不再只是研究概念，而是开发者愿意直接安装和依赖的工具。更值得注意的是，这类插件把“怎么记、何时注回”做成了工程问题，而不是抽象哲学问题。**影响评估：Coding Agent 正快速进入默认带记忆层的阶段，项目连续性会成为开发体验的新分水岭。**

**趋势分析**

1. **Agent 产品形态正从“对话框”转向“工作空间”。** OpenAI Projects 和 Marketing 教程一起说明，大厂已经不满足于卖一次性问答，而是在构建长期任务容器、部门模板和协作语境。
2. **记忆层正在从理念变成默认配置。** 从 hermes-agent 到 claude-mem，社区与产品侧同时证明，用户要的不是“会说”，而是“下次还能接着干”。
3. **模型路由与成本编排成为新基建。** “强模型先上还是后上”这种问题之所以升温，说明多步 Agent 的真正优化目标已转向整条链路的性价比与稳定性。
4. **监管与安全压力开始倒逼 Agent 工程化。** 英国监管评估 Anthropic 风险这类信号意味着，在金融等高敏行业，权限控制、审计与安全边界会越来越早进入采购和上线流程。
