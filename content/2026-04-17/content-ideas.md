## 创意 1：Coding Agent 真正升级的，不是会写代码，是会接整条工作流

- AI 味等级: 中。原始素材像产品更新摘要，缺真实工作场景、代价对比和明确立场。
- 标题候选：

- 目标受众：开发者、AI 工具重度用户、独立开发者
- 核心观点：2026 年 Coding Agent 的分水岭，已经从“谁补全得更快”切到“谁能接住完整工作流”。
- Hook 角度：从一个熟悉场景切入，真正耗时间的不是写那几行代码，而是在 IDE、终端、浏览器、文档之间来回切。
- 关键信息点：
  1. OpenAI 官方把 Codex 叙事从“写代码工具”推到了“电脑级代理”，强调可操作 Mac 应用、连接工具、记住偏好、接手重复任务。
  2. 中文开发者圈的高传播解读也在放大同一个点，不是更会写，而是更会“动电脑”。
  3. 资深工程师的真实项目对比讨论，正在把焦点从 benchmark 拉回到“8 万行项目里到底谁更能打”。
  4. 这和老板主线强相关，Agent、workflow、个人操作系统三条线在这里合流。
- 情绪价值：好奇 + 紧迫 + 实用
- 目标平台+优化建议：
  - **主平台：X Thread**
  - 开头先用第一人称判断，不要先复述发布会。
  - 第 2 条直接给一个真实开发场景，比如“开 PR、跑测试、改文档、回 issue”。
  - 结尾抛一个互动问题，“你愿不愿意把真实仓库先交给它 30 分钟？”
- 传播预测：★★★★★。官方产品升级 + 中文圈二次解读 + 开发者迁移讨论同时存在，今天就是窗口。

## 创意 3：独立开发别只晒收入，先晒账单

- AI 味等级: 高。原始素材如果只写“某产品月入 3 万美元”，很像成功学快讯，没有现实感，也没有经营视角。
- 标题候选：
  1. 人味版A：**我现在看独立开发案例，先看账单，不先看 MRR 截图**
  2. 人味版B：**月入 3 万刀不稀奇，API 只花 542 美元这事更值钱**
  3. 保守版：**独立开发案例里，比收入更该看的其实是成本结构**
- 目标受众：独立开发者、创业者、一人公司群体
- 核心观点：真正有用的创业样本，不是收入截图，而是成本结构、用户规模和 API 开销这些能复盘的经营细节。
- Hook 角度：大多数人看到 MRR 会兴奋一下就划走，但真正决定能不能学的是“这个钱怎么来的，又怎么花掉的”。
- 关键信息点：
  1. 开发者公开了 30K 美元月收入、39 万用户、OpenAI API 成本 542 美元的具体账单结构。
  2. 这类样本比抽象的“增长神话”更有现实价值，因为能看 unit economics。
  3. 对技术人来说，收入和利润不是一回事，分发成本、基础设施成本、工具依赖才是关键。
  4. 老板账号可以顺势输出“技术人做产品，要从写代码视角切到经营视角”。
- 情绪价值：实用 + 反鸡汤 + 降焦虑
- 目标平台+优化建议：
  - **主平台：小红书**
  - 用“账单拆解”做卡片感结构，正文写成 3 个我会先看的数字。
  - 标题尽量保留具体数字，收藏率会更高。
  - 结尾可以问一句，“你现在最不清楚的是获客成本，还是 API 成本？”
- 传播预测：★★★★★。数字具体，反鸡汤，有收藏价值，也很贴近技术人和独立开发者的真实焦虑。
- 时效窗口：3 天内都能发，今晚小红书发最合适。
- 写作体裁：拆账单 / 测评体
- 信息来源：research-materials.md（产品/创业 2）
- 核验状态：摘要级已核验

## 创意 4：AI 真正省下来的，不是写文案那几分钟，是整条知识整理链路

- AI 味等级: 中。原始“自动化知识管线”偏术语化，容易让人觉得懂很多但离自己很远。
- 标题候选：
  1. 人味版A：**我把邮件和会议纪要喂给 AI 后，周报终于不用熬夜了**
  2. 人味版B：**不是写文案快了，是我每周少做了 3 次重复整理**
  3. 保守版：**自动化知识管线，真正省下的是整理资料的时间**
- 目标受众：内容创作者、产品经理、研究型岗位、管理者
- 核心观点：AI 最值得做的不是替你写一段漂亮话，而是把邮件、文档、研究、会议这些碎工作串成一条自动化管线。
- Hook 角度：很多人还停留在“让 AI 帮我写”，但真正累人的常常是写之前那一大堆收集、整理、提炼。
- 关键信息点：
  1. 热门帖子展示了 Claude Cowork + NotebookLM 的自动化知识管线，把邮件、文档、研究自动变成会议简报和周报。
  2. 这条内容高收藏，说明大家在意的不是一次生成，而是持续复用。
  3. 这和老板的人设天然契合，研究、内容、产品都需要同一套 workflow。
  4. 可顺势延展到“把能力做成可复用技能资产”，而不只是省几分钟体力活。
- 情绪价值：轻松感 + 实用 + 想立刻照做
- 目标平台+优化建议：
  - **主平台：小红书**
  - 适合写成“我现在固定用的 3 步管线”，正文偏日记体或教程体。
  - 标题前 13 字尽量带“AI”“周报”“会议纪要”等搜索词。
  - 正文注意补具体场景，最后带 `#AI生成内容`。
- 传播预测：★★★★☆。收藏潜力高，适合老板长期主线，但需要用具体例子把术语拉回人话。
- 时效窗口：3-7 天，属于今天能发、下周也能复用的 evergreen 话题。
- 写作体裁：教程体 / 日记体

## 创意 5：一人公司的护城河，不是更努力，是你走开后系统还能跑

- AI 味等级: 中。原始素材容易写成管理术语，缺真实代价和个人经验感。
- 标题候选：
  1. 人味版A：**我休息一天，业务就停了，这不叫一人公司**
  2. 人味版B：**副业最扎心的一刻，不是没增长，是你不在线就没收入**
  3. 保守版：**一人公司的护城河，是你走开后系统还能继续跑**
- 目标受众：自由职业者、solopreneur、内容创业者、轻创业人群
- 核心观点：很多所谓一人公司，本质上只是创始人本人在线打零工，真正的护城河是流程文档化、收入结构化和现金流可视化。
- Hook 角度：用一个很扎心的判断开场，“你敢不敢完全离线两天，看业务会不会停摆？”
- 关键信息点：
  1. X 上关于 Solo Systems Architect、现金流可视化、收入结构地图的几条线开始合流。
  2. 一离开就停摆，说明业务依赖的是人，不是系统。
  3. 现金流看不清，本质上是风险看不清。
  4. 很多副业做了一年仍离不开自己亲自拧每颗螺丝，这正是系统没建立起来。
- 情绪价值：共鸣 + 刺痛感 + 可执行
- 目标平台+优化建议：
  - **主平台：知乎 / 小红书**
  - 知乎版适合写“怎么判断自己是在做生意还是在卖命”。
  - 小红书版可写成第一人称自白，再给 3 个自查问题，互动会更强。
- 传播预测：★★★★☆。不是全网爆款题，但非常贴老板受众，评论区会有真实共鸣。
- 时效窗口：5-7 天，适合本周内发，不依赖极强新闻时效。

## 创意 6：520 个新用户，为什么反而可能证明你做错了产品

- AI 味等级: 低。原始素材本身有反差，但如果直接写成“失败复盘值得看”，还是会偏摘要，缺现场感。
- 标题候选：
  1. 人味版A：**我见过最残酷的产品复盘，是 520 个新用户最后换来 0 MRR**
  2. 人味版B：**有流量没生意，这种失败比“月入十万”更该看**
  3. 保守版：**520 个用户也可能说明，你把产品方向做偏了**
- 目标受众：早期创业者、产品经理、独立开发者
- 核心观点：有用户不等于有业务，有流量不等于有留存，失败样本往往比成功学更能帮人避坑。
- Hook 角度：先给一个看似不错的数字，再立刻反转，“35 天、520 新用户、6 美元收入、0 MRR”。
- 关键信息点：
  1. 开发者公开承认上线 35 天后，520 新用户只带来 6 美元收入和 0 MRR。
  2. 这类失败比“增长神话”更有学习价值，因为它暴露的是定位和留存问题。
  3. 很多产品死得不是没人看见，而是没有持续价值和付费理由。
  4. 老板账号可以借这个案例讲“有用户”与“有业务”的区别。
- 情绪价值：反差 + 共鸣 + 醒脑
- 目标平台+优化建议：
  - **主平台：X / 小红书**
  - X 版适合一句反直觉开头，直接打脸“用户数焦虑”。
  - 小红书版建议写成失败日记，补 1-2 个踩坑细节，会更有人味。
- 传播预测：★★★★☆。失败复盘天然有反差，也更容易引发创业者评论区自曝经历。
- 时效窗口：48-72 小时较好，后续也可作为系列“反成功学”内容继续用。
- 写作体裁：失败复盘 / 测评体
- 信息来源：research-materials.md（产品/创业 4）
- 核验状态：摘要级已核验
