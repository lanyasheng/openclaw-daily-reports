## 设计方案

### 原则
1. **全量 vs 增量分层**：全量=每次覆盖当天完整判断、事件解读；增量=仅记录数值变化和差异
2. **时间窗口**：06:00~09:00 全量晨报 → 10:00~15:00 午间增量 → 15:00 后晚间增量/收盘总结
3. **保留粒度**：每日保留至少一份全量归档 + 时间戳增量合并到当日文件

### 归档文件结构（每个交易日）

```
knowledge/daily/2026-07-06/
├── daily-check.md          ← 全量晨报（07:00~08:00，包含执行摘要+仪表盘+深度分析）
├── heartbeat-status.md     ← 开盘后心跳（10:00~11:00，精简、增量格式）
├── evening-market-review.md ← 晚间/收盘总结（20:00+，增量格式，引用晨报）
├── 01-followup-open-items.md ← 开项闭环
└── blocker-*.md / evidence-*.md ← 改进事项
```

### 增量格式规范

**heartbeat-status.md 和 evening-market-review.md 使用精简格式：**

```
# 标题 — 仅展示当天delta数据

## 🔄 较上次有什么变化
- 指数变化（仅列变动 >0.3% 的）
- 事件更新（当日新发）
- 定级变化（None → Watch / Watch → Alert）

## 📊 关键数值（仅该时段 snapshot）
| 指标 | 当前值 | Delta vs 晨报 |

## ⚡ 核心判断
- 维持/升级/降级，引用晨报 ID
```

### 隔夜文件自动清理规则
- content/report/: 保留天数=14
- knowledge/daily/YYYY-MM-DD/: 保留天数=30，超过的移入 archive/YYYY-MM-DD/
- archive/: 保留天数=90，超过的由 system 清理
